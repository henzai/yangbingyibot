## Architecture

Discord bot on Cloudflare Workers. Uses Google Gemini AI with a Google Sheets knowledge base. Cron health check (every 5 min) reports failures as GitHub Issues.

### Request Flow

1. `src/index.ts` — Hono app. `POST /` runs `verifyDiscordInteraction` (Ed25519 signature check) before any handler logic.
2. `InteractionType.PING` → immediate `PONG`. `InteractionType.APPLICATION_COMMAND` → `loadConfig` fails fast, `parseDiscordAskCommand` validates the `/ask` command, then a `ANSWER_QUESTION_WORKFLOW` instance is created and `DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE` is returned (Discord's 3 second budget).
3. `AnswerQuestionWorkflow` (`src/workflows/answerQuestionWorkflow.ts`) runs the durable steps: `getSheetData` → `getHistory` → `streamGeminiAndEditDiscord` (no retries, 120s timeout) → `saveHistory`.
4. During streaming, `onChunk` throttles Discord PATCH edits (thinking phase: 1000ms / 200 chars via a summary model; response phase: 1500ms / 50 chars) and forces an edit on the first thinking chunk and on the thinking→response transition.
5. `src/discord/delivery.ts` owns all delivery: `splitContent` chunks at the 2000 UTF-16 code unit limit on newline/space boundaries without splitting surrogate pairs, the first chunk is a PATCH to `@original` and the rest are POST follow-ups, each with bounded retries (3 attempts, 1s→10s exponential). Results are reported as `success` / `partial` / `failed` / `empty` rather than throwing.
6. On workflow failure, the error is reported to GitHub Issues **outside** `step.do()` (so Workflow retries do not duplicate reports) and an error message is delivered to Discord.
7. `scheduled` runs `runHealthCheck` (`src/health.ts`) — KV, Gemini API, and Google service account checks in parallel; failures become GitHub Issues.

### Caching and State (KV binding `sushanshan_bot`)

- **Sheet cache** (`src/repositories/sheetCache.ts`) — key `sheet_info:v2:<sha256 of spreadsheet id + sheet names>`, TTL 5 minutes. Reads and writes are best effort; a cache failure never fails the request.
- **Conversation history** (`src/repositories/conversationHistory.ts`) — key `chat_history:v2:<conversationKey>`, TTL from `HISTORY_TTL_SECONDS`. Trimmed to the last 20 entries and 64KB before writing. `conversationKey` is a SHA-256 of `guildId|dm:channelId:userId`, so history is per user per channel.
- **Report deduplication** (`src/repositories/deduplicationStore.ts`) — key `error_reported:<fingerprint>`, TTL 1 hour. Layer 1 of a two-layer dedup; layer 2 is a GitHub Issues search.

### Observability

`src/clients/metrics.ts` writes to the optional `METRICS` Analytics Engine binding, falling back to `NoOpMetricsClient` when the binding is absent. `src/utils/logger.ts` emits structured JSON logs with `withContext` (requestId, workflowId, step).

## Project Structure

```
src/
  index.ts                  # Hono app, Discord interaction entrypoint, scheduled handler
  config.ts                 # Env validation + DEFAULT_RUNTIME_CONFIG fallbacks
  contracts.ts              # Bindings, WorkflowParams, HistoryEntry (dependency-free)
  health.ts                 # Cron health check + GitHub Issue reporting
  clients/                  # discord, gemini, github, metrics, spreadSheet
  discord/                  # delivery (chunking/retry), formatter, interaction parsing
  middleware/               # verifyDiscordInteraction (Ed25519 signature)
  repositories/             # conversationHistory, sheetCache, deduplicationStore (KV)
  responses/                # errorResponse
  utils/                    # compactSheet, errors, logger, requestId, retry
  workflows/                # answerQuestionWorkflow, types
scripts/                    # commands.js (slash command definitions), register.js
wrangler.toml               # Bindings, cron trigger, Workflow registration
worker-configuration.d.ts   # Generated by `npm run cf-typegen` — do not edit by hand
```

Tests live next to their source as `*.test.ts` and run on `@cloudflare/vitest-pool-workers`.

## Environment Variables

Cloudflare bindings (defined in `wrangler.toml`, typed in `src/contracts.ts`):

- `sushanshan_bot` - KV namespace for the sheet cache, conversation history, and report deduplication
- `ANSWER_QUESTION_WORKFLOW` - Workflow binding for `AnswerQuestionWorkflow`
- `METRICS` (optional) - Analytics Engine dataset `yangbingyibot_metrics`; metrics are no-ops when unbound

Required in Cloudflare Workers secrets or `.dev.vars` for local development:

- `DISCORD_TOKEN`, `DISCORD_PUBLIC_KEY`, `DISCORD_APPLICATION_ID` - Discord credentials
- `GEMINI_API_KEY` - Google Gemini API key
- `GOOGLE_SERVICE_ACCOUNT` - Google Service Account credentials (JSON string)
- `GITHUB_TOKEN` (optional) - GitHub PAT for auto-reporting errors and health check failures as Issues

Optional runtime configuration (current production values are used when omitted):

- `GEMINI_MODEL`, `GEMINI_SUMMARY_MODEL` - Answer and thinking-summary models
- `GOOGLE_SPREADSHEET_ID`, `GOOGLE_DATA_SHEET_NAME`, `GOOGLE_DESCRIPTION_SHEET_NAME` - Google Sheets source
- `GITHUB_REPOSITORY` - Error-report destination in `owner/repository` format
- `HISTORY_TTL_SECONDS` - Conversation history TTL (60–86400 seconds, default: 300)

## Git Workflow

- 新しいブランチは、明確に既存ブランチの作業を引き継ぐ場合を除き、必ず `main` から作成すること。作成前に `git fetch origin` を実行し、`origin/main` から作成すること
- PRを作成する際は、対象の変更に関係ないコミットが含まれていないことを確認すること
- TODOリストの各項目が完了するごとにコミットを作成すること

- PRが存在しない場合はドラフトPRを作成すること
