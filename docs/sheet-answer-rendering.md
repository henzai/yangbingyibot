# 作業D：集合を検証して描画する

レビューはこの冒頭と表のみ、約3分です。判断点は「共通検索実行器の結果を検算し、一覧・集計の描画と実配信IDの記録をこの層に任せる方針」の1点です。推奨は可です。#509の期違い・抜け・件数不一致を検出でき、E/Fの接続でも同じ実行器を使えます。返答は「この方針でよい」または懸念点だけで十分です。mergeには別途明示承認を必要とします。

| 23期／24期の回帰 | 人工fixtureでSNH48 23期20人＋24期9人。漢数字・全角数字を共通の期解析で扱い、別グループ・22期を除外。複数所属・予備生・暫休/退団の併記を残す。グループ省略は要確認 |

Epic #512、設計PR #513、作業C #515、実装トラック #509 に対応する共通層です。本PRは自然文の質問をルーティングしたり、本番の誤答が解消したと判定したりするものではありません。検索ツール接続後の品質・費用・遅延と本番受け入れはE/F/Gに残ります。

## 呼び出し契約

入口は `src/sheets/answers/prepare.ts` です。引数に渡すのは質問開始時に開いた `SheetSearchEngine` と型付き条件だけです。元データを別途読み込む抽出器や、モデルに作らせたページは使いません。

- `prepareQueryAnswer(engine, queryArgs, limits?)`：membersの完全な条件集合を描画します。氏名・ピンイン・期・本所属・兼任先・新人組・状態と指定列、sort列を同じ実行器で取得します。追加後の20列上限も検証します。
- `prepareGenerationAnswer(engine, {group, generations}, limits?)`：上と同じ実行器への薄い補助です。期の数字/漢数字は既存のsnapshot解析を再利用し、グループと期の完全一致条件を作ります。グループ未指定は `missing_context`、期の不正は `invalid_arguments`。自然文や会話からのグループ同定はE/Fの責務です。
- `prepareAggregateAnswer(engine, aggregateArgs, limits?)`：count/mean/min/max/best_rank/differenceと組別集計をコードで描画します。同値者はhandleの全IDから同じsnapshotで詳細を取得します。数値は丸め前の値を表示し、平均の有効人数・欠損内訳を残します。日付計算は実行器に固定した計算日を再利用します。
- `verifyAnswerSelection(engine, resultSetId, {snapshot_id, ids, count})`：後続が構造化出力の集合を使う場合の検算です。同名でもIDで区別し、重複・欠落・別集合混入・件数/版の不一致を拒否します。自由文から名前を推測して照合しません。

結果は `PreparedSheetAnswer` または値を含まないエラーです。候補や文字列一致の集合をこの入口で完全な条件集合として扱いません。exact_setが保証するのは指定条件との一致です。自然文の意図と条件が一致するかは別に評価します。

全ページでsnapshot/規則版/条件/計算日/件数/handleの一貫性、cursorの進行、最終ページまでの取得、全IDと件数を検証します。断片セル・未取得ページ・不整合は成功にせず、エラーを返します。元snapshotの期限切れ・欠落でも現時点のSheetsへ置換しません。巨大な1行を黙って短縮せず、描画予算エラーにします。自由記述の長文復元は作業Cのget契約を使う後続の別経路です。

## 表示準備と実配信

`answer.chunks` は内容と、そのchunk内で**行全体を表示するID**を持つコピーです。行の途中で分割しません。氏名が欠損・数式エラーでもID付き行を保持し、元データにある状態を推測で上書きしません。セルはinlineのデータとして描画し、改行・Markdown・mention・scheme URLと裸のドメイン表記を無効化します。Fのtransportでもallowed_mentionsの無効化とembed抑制を維持する必要があります。

既定は1chunk 2,000 UTF-16単位、最大8chunk、内部収集100ページ/累積512KiB。150人の人工一覧をこの既定で全取得し、表示を一部に制限するケースを確認します。後続は `limits` で狭められます。上限は100chunk/1,000ページ/2MiBで、それ以上の指定を拒否します。これはDのローカル準備予算で、Fの全モデル往復・検索・retry・Discord配信の共通deadline/token予算を代替しません。

表示上限では全chunkへ未完了表示を付け、`omittedIds`（未表示の人物ID）と `omittedEntries`（見出しを含む未表示の項目数）で未表示範囲を残します。`deliveryState().undelivered_ids` は表示省略と未送信/配信失敗の両方を含みます。条件・順位・分類の不明は人数を明示し、確実な全員/首位の断定を避けます。集計の母集団IDは、名前を表示した人物のIDとは異なります。countだけを配信しても母集団全員を「名前を配信済み」にしません。

Fは各chunkをそのまま配信し、transportの成功確認後にだけ `answer.confirmDelivered([{index, content}])` を呼びます。未送信・preview・送信試行・失敗chunkを成功として記録しません。同じindexの再確認は重複計上せず、不正indexや予定と異なる本文を含む更新は全体を拒否します。`deliveryState()` は成功chunk由来のIDと未配信ID、unsent/partial/completeを返します。取得・描画が全件でも、配信が失敗したらcompleteになりません。

後続の「他には」はこの実配信IDだけを会話metadataへ保存し、次の質問の新しいsnapshot上で条件を取り直します。Workflowのcheckpoint保存、送信前後の中断、Discord transportの再試行や重複送信の制御はFで実装・検証します。この層自体は送信しません。

## 検証と残るゲート

人工データで20＋9全件、期/グループ分離、状態併記、同名別ID、AND/OR、上位・全同値、平均/差分/年別順位、0件、欠損、複数所属、改変ページ/集合、期限、ページ/byte/表示上限、実配信IDの区別を検証します。検索・描画からの外部fetchは0回で、実シート・Discord履歴・質問コーパスをfixtureへ含めません。最終結果はPR本文に記録します。
